# Brand reference delivery

## 7. Publish an accurate, living /brand reference

Only publish approved, privacy-clean material with authorization. Keep discovery, raw participant data and rejected work private unless separately cleared.

Include foundations and behavioural principles; voice and copy pairs; approved logo masters and usage rules; colour roles and measured pairings; type and licensed fonts; image/composition/interaction principles; representative applications; working editable templates; CSS/JSON tokens; Markdown guidance; and a small agent-readable discovery index. Add owner, version, approval state and change history.

Use one canonical token/asset source and verify parity across the website, Markdown, downloads and code. Test deployed routes and downloads, not just the build. Distinguish delivered templates from promised ones. Document intentional co-branding exceptions rather than recolouring other identities.

**Output/gate:** verified public reference and working assets. Revisit when beliefs, audience understanding or actual work changes—not merely because the team is bored with its logo.
